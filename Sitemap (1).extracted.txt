follow:

3.2 Mobile Bottom Tab Bar (persistent, fixed)
Standard for shopping apps — improves conversion vs. relying on header alone:
Tab 	Links to

3.3 Mobile-Specific Behavior Changes
Filters (Product Listing Page): desktop sidebar becomes a mobile bottom
sheet/drawer triggered by a “Filter” button, not permanently visible
Product grid: 2 columns on mobile vs. 3 on desktop
Build Your Own Hamper step indicator: desktop horizontal stepper
becomes mobile compact “Step 3 of 6” text plus a progress bar (avoid
cramming 6 circles on small width)
Checkout order summary: desktop sticky sidebar becomes a mobile
collapsible summary bar pinned above the “Place Order” button
Image galleries (PDP): desktop thumbnail strip beside the image becomes a
mobile swipeable carousel with dot indicators below the image
Tables (Nutritional Info, etc.): must remain horizontally scrollable or stack
into label-value pairs — never overflow/break layout
WhatsApp floating button: repositions to avoid overlapping the bottom tab
bar

5. Notes for Build Agent
Build Your Own Hamper is a linear wizard — Steps 2–6 must redirect to Step
1 if session/budget state is missing; no direct URL skipping.
Track Order is intentionally public — only an Order ID is required, since gift
recipients (not just the buyer) may track a delivery.
Admin routes ( /admin/* ) sit in a fully separate protected namespace — never
linked from customer-facing nav or footer. See the SecurityArchitecture
document for access-control rules.
Checkout requires authentication; Cart does not — guest users can add to
cart and are prompted to log in only at “Proceed to Checkout.”
Mobile is not a scaled-down desktop — the bottom tab bar, filter bottom-
sheets, and carousel patterns above are structural changes, not just
responsive CSS resizing. Build mobile layouts as first-class, not an
afterthought.
