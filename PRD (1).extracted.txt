1. Overview
Product: Sukhmal Dry Fruits Korner — a premium D2C e-commerce website
selling dry fruits, nuts, seeds, dates, berries, and curated gift hampers, with a
strong festival and wedding-gifting focus.
Business model: Direct online sales (retail) + gift hamper customization +
bulk/corporate gifting orders.

-- 1 of 9 --

Primary goal: Build a pixel-accurate, secure, production-ready frontend and
backend from the attached UI Screens, matching the provided design exactly — no
visual reinterpretation.
Target users: - End customers buying dry fruits/nuts for personal consumption -
Gift buyers (festivals, weddings, birthdays, corporate gifting) - Repeat/loyalty
customers with saved addresses and order history - Store admin (product, order,
and inventory management — separate access level)

5. Authentication & Roles
Customer auth: Firebase Authentication (email/phone + password, or OTP)
— required for Checkout, Wishlist persistence, My Account, Order History
Guest flow: browsing, cart, product/hamper viewing allowed without login;
login required only at checkout
Admin role: separate Firebase custom claim ( role: admin ), separate
protected route namespace, own login — never exposed on the customer-
facing UI
Full auth boundary rules to follow the separately supplied
SecurityArchitecture document — this PRD defines what needs protecting,
not the security implementation itself

7. Non-Functional Requirements
Fully responsive: desktop, tablet, mobile (mobile variant explicitly supplied for
Track Order — apply same responsive discipline sitewide)
Page load performance: lazy-load below-the-fold images and carousels
SEO-friendly URLs and meta tags per product/category/hamper page
All forms client + server-side validated
WCAG-reasonable accessibility (alt text, contrast, keyboard nav) — not a
redesign excuse, keep within supplied visual design
Currency: INR (₹), GST-inclusive pricing shown at cart/checkout

9. Design Fidelity Instruction (for the
build agent)
All 23 supplied UI Screens are final, approved, high-fidelity designs. Match them
exactly — layout, spacing, typography, color, iconography, component states, and
copy. Do not substitute default styling, do not “improve” or reinterpret the design.
Refer to the separately supplied DesignSystem document for exact tokens (colors,
fonts, spacing scale). Where a screen shows a specific interaction (e.g., live-
updating hamper summary, char-count fields, progress percentage on preview),
implement that exact behavior — not an approximation.
